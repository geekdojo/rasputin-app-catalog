# Standard exceptions — rasputin-app-catalog

Approved departures from the [Geekdojo development principles](https://github.com/geekdojo/geekdojo-brain/blob/main/engineering/development-principles.md) and from this repo's binding [tile secrets guide](docs/tile-secrets.md).
The process and this table's format are in [Standard exceptions](https://github.com/geekdojo/geekdojo-brain/blob/main/engineering/standard-exceptions.md).
A departure that matches a row here is not a review finding. When a row's revisit fact becomes true,
the code is brought into line, the row is removed in the same change, and the approving Issue is closed.
IDs are never reused.

| ID | Rule | Where | Departure | Constraint | Revisit fact | Approved |

| EX-1 | `R4` ([tile secrets](docs/tile-secrets.md#r4-never-ship-a-literal)) | `tiles/romm/docker-compose.yml` service `romm-db-bridge`: `LEGACY_DB_PASSWORD`, `LEGACY_ROOT_PASSWORD`; `tiles/immich/docker-compose.yml` service `immich-db-bridge`: `LEGACY_DB_PASSWORD` | The two one-shot bridge services carry the database passwords these tiles published before they used the platform's secrets (`romm`, `romm-root`, `immich`) as literal environment values. The bridge uses them only to log in to a database still on them and change its passwords to the platform's. The app and database services carry only tokens. | `true-now`: both databases apply their password only when they first create their data directory, so an upgraded install keeps the published passwords. MariaDB `12.3.3@sha256:d46e102f…` runs `docker_setup_db` only when `DATABASE_ALREADY_EXISTS` is empty (`docker-entrypoint.sh:294-296`, `:703`) and gives root password authentication, not the local socket (`:234`); the immich Postgres `14-vectorchord…@sha256:bcf63357…` sets up only when `PG_VERSION` is absent (`/usr/local/bin/docker-entrypoint.sh:254-259`). Nothing lets a tile or an owner write a value for a derived secret name (rasputin-control-plane `api/internal/secrets/service.go` `authorize`; `api/internal/apps/operatorsecrets.go` `ErrOperatorSecretNotDeclared`), so the published value is the only credential an upgraded database accepts from inside the tile. | No installed copy can still be on a catalog version from before the bridge (for example, [geekdojo/geekdojo-brain#581](https://github.com/geekdojo/geekdojo-brain/issues/581) ships a forced upgrade past it), or the control plane can write a derived secret entry for an app on upgrade. | [geekdojo/geekdojo-brain#1056](https://github.com/geekdojo/geekdojo-brain/issues/1056); Bryce's RULING-521-A on [geekdojo/geekdojo-brain#521](https://github.com/geekdojo/geekdojo-brain/issues/521#issuecomment-6589934269) |
